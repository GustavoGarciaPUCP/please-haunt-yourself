## What was still incomplete and is now decided

1. **A visible first-run route:** a playable creative workshop still needs a guided path through its four operations. The route below provides contextual next steps without locking the OS behind four tutorial checkboxes.
2. **A coherent single-decision branch:** public and backstage entrance attachments must expose the same declared admission object, so a compatible suffix can remain valid without magical retargeting.
3. **A boundary between animation and game state:** ECHO cannot appear because a timer expired while an opaque panel is still arriving, nor can an obsolete animation callback reopen a departed visit.
4. **Save/reload and interruption:** quiet failure states need defined recovery, not cinematic polish over lost work.
5. **A demonstration of audience value:** the project is a short creative play experience for technology/interactive-fiction enthusiasts. It does not claim unmeasured educational gains, social impact or invented audience size.

## Shared entry resolves the useful branch

The initial invitation contains preview, public entrance and optional backstage access. Opening either entrance attachment is a route choice **before admission**:

- **Open Public entrance:** reveal the public entry view and its admission control.
- **Open Backstage pass:** reveal anxious preparation and its admission control.
- Both expose the **same declared object**, `show.entry`, with the visible action **Join the show**. Executing it emits the existing Performance entered event.

Opening Preview never exposes admission implicitly or begins a performance. Its explicit route links, if present, remain separate actions.

An example branch can therefore change **Open Backstage pass** to **Open Public entrance** and preserve a following **Join the show** action on the same `show.entry` object. The visitor has genuinely learned something different before the same admission. This is not retargeting two unrelated buttons after the fact.

This compatibility applies only where both accesses were received. Other suffix actions remain subject to09's access and phase checks. If an original suffix references an exclusively backstage object, it still blocks on a public-only route. The system does not quietly replace it. A historical guest's envelope is unchanged; a new-envelope rehearsal is a new identified context under10.

Planned timings below are initial values to tune against actual renders. They are not observations. |10, actual returned-view postcard | Occasional new artifact | Feedback + spatial consistency | Card arrives8px from its originating envelope with opacity over220ms | Historical cards do not animate every rerender; data/revision is already fixed |

The story beat can exceed the duration of one UI transition because its order conveys cause and effect. It must not turn into a long non-interactive cutscene. These are starting motion budgets, not a proven performance profile.

**Rejected motion:** continuously flickering readable text; bouncing taskbar icons; animated keyboard focus/navigation; delayed primary actions; pointer trails presented as recorded behavior; background particle loops competing with the actor; simultaneous panel entrance plus child stagger. Each either recurs too frequently, distracts from functional information or blocks the action it should explain.

### State and interruption contract

1. Logical phases and09's recorded-departure checkpoints are authoritative. CSS durations are not a hidden game clock or a score.
2. Direct dragging updates the staged position without momentum. A replayed mask entrance may be animated, but **Appearance ready** is reached only when its presented surface is fully opaque and settled, with public visibility valid. A duration estimate alone cannot claim coverage.
3. Leave is processed before same-checkpoint appearance. Cancel the current visit's pending cues and presentation work. No completion callback may append a late appearance, postcard or success result.
4. Every presentation callback belongs to the current visit/run and phase. Changing mode, restarting or leaving invalidates earlier callbacks. Completion is idempotent; finishing a canceled animation cannot emit the same event again.
5. Reduced motion reaches the same semantic checkpoints with stable poses. Process pending recorded departure before advancing an appearance checkpoint, even when presentation settles immediately. It must not convert an interrupted recording into a complete show.
6. Edit show stops Replay, retains committed production data and resets transient actors/cues. Unconfirmed body manipulation is canceled or explicitly committed; it cannot leave a mismatched actor and source gap.
7. Double activation does not create duplicate bodies, deliveries, visitor runs or saves. Rapid scene changes cancel old visual work; the last explicit choice owns the active scene.
8. If the browser tab becomes hidden, pause the performance and do not award unseen completion. Returning offers Resume from the same checkpoint or Edit show. This is scoped to the new fictional show; old paper-bridge tests do not prove it.

## Save, recovery and meaningful endings

Save a consistent committed revision; animation playheads and unfinished pointer gestures are not the production's initial state. A body edit invalidates the public poster/Subscriber evidence as specified in10. Every result identifies the configuration and invitation it exercised.

If browser storage is unavailable or writing fails, keep the draft in memory, report **Not saved on this device**, offer the bounded show-package download when available, and preserve Edit show. Do not display Saved or close the console as successful persistence. Do not require an external account or cloud service to recover normal progress.

Reloading resumes the latest successfully saved draft in Edit show, not half-way through a simulated visit. It never invents departure or advances an unfinished guest while the player was absent. Unsupported/corrupt saved data produces a clear recovery choice without overwriting the last readable save. Arbitrary import/migration tooling remains outside the baseline; no executable uploads or unrestricted external assets are added.

The ending is still the saved desktop with the user's actual body, reaction, route contexts and observed cards. Completing four tutorial checkboxes or watching a cinematic is insufficient evidence of a working production.
