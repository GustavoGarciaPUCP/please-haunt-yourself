## Concrete design correction

| Technical presentation | Default Halloween interaction | Actual state consequence |
| --- | --- | --- |
| archive | A handwritten last note; keep it or let it fade | Retained message versus a genuinely blank archive and different ending |
| stdout | A whisper belonging to the visible ghost | Hushing stops its voice, not its ability to return |
| on_exit callback | A summoning bell answering every departure | Quieting it prevents the next return |
| Step execution | Watch the next moment | Observe note → whisper → summons; the model really advances |
| TERM | Guide it out | A clean farewell can free the terminal |
| KILL/residue | Force it out / a shadow left behind | An abrupt ending remains recoverable and does not claim a repair |

Keep the two real clean endings and Undo. The human-facing narration and pose/objects must communicate each consequence without interpreting PID/BASIC/callback text. A clearly optional Under the hood inspector retains real engine state/code/commands for interested players. The native functional console remains available, but typing commands is not necessary to play the encounter.

## Visual direction and effects

Use a spectral, ink-like original SVG ghost inside the terminal; its eyes/voice/opacity follow the same health/output state. An amber moon, a note and bell belong to the ritual rather than unrelated pumpkin stickers. A ghostly sentence writes itself in a bounded text reveal, without stealing keyboard input or interpreting source. Hushing must leave the ghost visible; a successful farewell must clear the presence. Recovery changes both the terminal skin and real command behavior as task16 already specifies.

No mandatory sound, flickering/glitch storm, timers to solve, fake host-OS access or repeated jumpscares. Use visible bell/voice cues. Reduced motion shows complete words/stable states immediately. Product copy is English; plain actions before technical labels. Maintain keyboard/button equivalence, view cancellation and mobile scroll/contrast.

## Kiro IDE implementation, November 6

This section was written by the Kiro IDE run. The session context reported Claude Opus 5.5; the effort setting and credits were not visible. The spec and its critique are in `.kiro/specs/terminal-halloween/`.

**Implemented.**
- Both views read the same model:
  - **Shell.** A ghost behind the banner writes the farewell once per opening and once per new return. Follow the ghost, Are you okay? and Read the note need no typing. A visual bell appears in the console tab after the first return.
  - **The ghost's room** inside the same window. Mara's note, the ghost and its whisper, and a shop-door bell above "the way out".
- **Actions.** Watch the next moment, Hush the whisper, Keep or fade the note, Quiet the bell, Guide it out, Force it out, Call the shadow back and Undo all map to the existing model calls.
- **Narration.** It names the cause of every return, including the player's own failed farewell. Changing an object never moves the ghost.
- **Endings.** Both clean endings clear the presence and leave a different banner, check-in, note and desktop line. Forcing leaves an eyeless shadow.
- **Optional parts.** Under the hood is a closed disclosure holding PID, trace, BASIC, the `on_exit`/TERM/KILL mapping and typed commands. Bell sound is an opt-in chime.
- **Motion and access.** Reduced motion shows complete words and still poses.

**Process semantics** are unchanged. Only presentation fields (`lastAction`, `recalled`/`threshold`) and check-in wording changed.

**Verified:** build, 63 unit tests, and 46 browser journeys across six checks.
